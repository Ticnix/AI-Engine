# 工作流模块 — 可视化 DAG 流程引擎

工作流模块是整个项目最复杂的子系统。它提供了一个可视化的 DAG（有向无环图）编辑器，用户可以拖拽 13 种节点类型来编排 AI 处理流程，并通过拓扑排序引擎逐层执行。

## 一、数据库模型

```prisma
model Workflow {
  id          String   @id @default(cuid())
  name        String
  description String?
  nodes       Json     // React Flow 的节点定义（位置、类型、数据）
  edges       Json     // React Flow 的连线定义
  status      String   // draft / published / archived
  userId      String
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  user        User             @relation(fields: [userId], references: [id])
  apps        App[]            // 被智能体引用
  executions  WorkflowExecution[] // 执行记录
}

model WorkflowExecution {
  id            String   @id @default(cuid())
  workflowId    String
  status        String   // running / success / error / cancelled
  input         Json?
  output        Json?
  error         String?
  startedAt     DateTime @default(now())
  completedAt   DateTime?

  workflow      Workflow       @relation(fields: [workflowId], references: [id])
  nodeExecutions NodeExecution[] // 各节点执行详情
}

model NodeExecution {
  id             String   @id @default(cuid())
  executionId    String
  nodeId         String
  nodeType       String
  status         String   // running / success / error / skipped
  input          Json?
  output         Json?
  error          String?
  startedAt      DateTime @default(now())
  completedAt    DateTime?

  execution      WorkflowExecution @relation(fields: [executionId], references: [id])
}
```

## 二、节点类型（13 种）

### 按功能分组

| 分组 | 节点类型 | 图标 | 说明 |
|------|----------|------|------|
| **流程控制** | trigger | ⚡ 闪电 | 触发器，流程入口，接收初始输入 |
| | condition | 🔀 菱形 | 条件判断，True/False 两个分支 |
| | loop | 🔄 循环 | 遍历数组，对每个元素并行执行子流程 |
| | output | 📤 输出 | 流程出口，收集最终结果 |
| **AI 能力** | llm | 🤖 机器人 | 调用 Ollama LLM 生成文本 |
| | retrieval | 📚 书本 | 向量检索，从知识库检索相关片段 |
| | intent | 🎯 目标 | 意图识别，判断用户输入的分类 |
| **数据处理** | http | 🌐 网络 | 发起 HTTP 请求 |
| | subworkflow | 📦 盒子 | 调用另一个工作流 |
| | code | 💻 代码 | 执行自定义 JavaScript 代码 |
| | message | 📨 消息 | 发送通知（Webhook/Email） |
| | varset | 🔧 工具 | 设置变量值 |
| | texttemplate | 📋 模板 | 文本模板渲染 |

### 节点的连接规则

```
trigger → 只有一个 source 出口，无 target 入口
llm → 有 target 入口（接收上游输出）和 source 出口
retrieval → 同 LLM
condition → 有 target 入口，两个 source 出口（True 左 / False 右）
output → 只有 target 入口，无 source 出口（终点）
其他 → 都是 target + source（中间节点）
```

### 10.2 拓扑排序 — `src/lib/workflow/topology.ts`

```typescript
interface TopologyResult {
  order: string[];        // 执行顺序（节点 ID 数组）
  layers: string[][];     // 分层（每层可并行）
  hasCycle: boolean;      // 是否有环
  entryNodes: string[];   // 入口节点
}

// Kahn 算法（BFS）
export function topologicalSort(
  nodes: WorkflowNode[],
  edges: WorkflowEdge[]
): TopologyResult {
  // 1. 构建入度表和邻接表
  const inDegree = new Map<string, number>();
  const adjList = new Map<string, string[]>();

  // 2. BFS 逐层处理
  const queue = nodes.filter((n) => inDegree[n.id] === 0).map((n) => n.id);
  const layers: string[][] = [];
  const order: string[] = [];

  while (queue.length > 0) {
    layers.push([...queue]); // 当前层可并行
    const nextLayer: string[] = [];
    for (const nodeId of queue) {
      order.push(nodeId);
      for (const neighbor of adjList[nodeId]) {
        inDegree[neighbor]--;
        if (inDegree[neighbor] === 0) nextLayer.push(neighbor);
      }
    }
    queue.length = 0;
    queue.push(...nextLayer);
  }

  // 3. 环检测
  const hasCycle = order.length !== nodes.length;

  return { order, layers, hasCycle, entryNodes: /* ... */ };
}
```

### 分层执行示例

```
层 1: [trigger]        ← 只有触发器，无依赖
       ↓
层 2: [llm-1, retrieval-1]  ← 两个节点并行（都只依赖 trigger）
       ↓         ↓
层 3: [condition]        ← 依赖 llm-1 和 retrieval-1 的输出
       ↓
层 4: [http-1, code-1]   ← True 和 False 分支的节点
       ↓
层 5: [output]           ← 收集结果
```

### 10.3 变量解析 — `src/lib/workflow/variable.ts`

```typescript
// 支持两种语法：
// {{input.field}}           → 从 context.inputs 中取值
// {{nodeId.output.field}}   → 从 context.outputs.get(nodeId) 中取值

export function resolveVariable(
  variable: string,
  context: ExecutionContext
): any {
  // {{input.name}} → context.inputs.name
  if (variable.startsWith("input.")) {
    const field = variable.slice(6);
    return context.inputs[field];
  }

  // {{llm-1.data.content}} → context.outputs.get("llm-1").data.content
  const [nodeId, ...parts] = variable.split(".");
  const nodeOutput = context.outputs.get(nodeId);
  if (!nodeOutput) return undefined;
  return parts.reduce((obj, key) => obj?.[key], nodeOutput);
}

// 字符串中的 {{变量}} 替换
export function resolveVariablesInString(
  template: string,
  context: ExecutionContext
): string {
  return template.replace(/\{\{([^}]+)\}\}/g, (_, varName) => {
    const value = resolveVariable(varName.trim(), context);
    return value !== undefined ? String(value) : `{{${varName}}}`;
  });
}

// 条件表达式评估
export function evaluateCondition(
  expression: string,
  context: ExecutionContext
): boolean {
  // 先替换变量，然后用 Function 构造函数执行
  const resolved = resolveVariablesInString(expression, context);
  return new Function(`"use strict"; return ${resolved}`)();
}
```

export function formatSSE(event: string, data: any): string {
  return `event: ${event}\ndata: ${JSON.stringify(data)}\n\n`;

// 创建 SSE ReadableStream
export function createSSEStream(
  eventIterator: AsyncIterable<ExecutionEvent>
): ReadableStream {
  return new ReadableStream({
    async start(controller) {
      for await (const event of eventIterator) {
        controller.enqueue(new TextEncoder().encode(formatSSE(event.type, event.data)));
      }
      controller.close();
    },
  });
}

### 10.5 执行引擎 — `src/lib/workflow/engine.ts`

```typescript
interface ExecutionEvent {
  type: "start" | "node" | "data" | "layer" | "error" | "done";
  data: any;
}

interface WorkflowOverride {
  nodes: any[];  // 前端传来的画布节点
  edges: any[];  // 前端传来的画布连线
}

async function* executeWorkflow(
  workflowId: string,
  inputs: any,
  userId: string,
  override?: WorkflowOverride
): AsyncGenerator<ExecutionEvent> {
  // 1. 加载工作流
  const workflow = await prisma.workflow.findUnique({ where: { id: workflowId } });
  const nodes = override?.nodes || workflow.nodes;
  const edges = override?.edges || workflow.edges;

  // 2. 创建执行记录
  const execution = await prisma.workflowExecution.create({
    data: { workflowId, status: "running" },
  });

  // 3. 拓扑排序
  const topology = topologicalSort(nodes, edges);
  if (topology.hasCycle) {
    yield { type: "error", data: { message: "存在循环依赖" } };
    return;
  }

  // 4. 创建执行上下文
  const context: ExecutionContext = {
    inputs,
    outputs: new Map(),
    workflowId,
    executionId: execution.id,
    userId,
  };

  // 5. 逐层执行
  for (const layer of topology.layers) {
    yield { type: "layer", data: { layerIndex: /* ... */ } };

    // 并行执行当前层
    const results = await Promise.allSettled(
      layer.map(async (nodeId) => {
        const node = nodes.find((n) => n.id === nodeId);
        const handler = getHandler(node.type); // 获取对应 handler

        yield { type: "node", data: { nodeId, type: node.type } };

        try {
          const result = await Promise.race([
            handler.execute(node, context),
            new Promise((_, reject) =>
              setTimeout(() => reject(new Error("超时")), 60000)
            ),
          ]);

          // 条件分支跳过
          if (shouldSkip(node, context)) {
            context.outputs.set(nodeId, { skipped: true });
            yield { type: "node", data: { nodeId, status: "skipped" } };
            return;
          }

          context.outputs.set(nodeId, result.data);
          yield { type: "node", data: { nodeId, status: "success", output: result.data } };

          // 记录节点执行详情
          await prisma.nodeExecution.create({
            data: { executionId: execution.id, nodeId, nodeType: node.type, /* ... */ },
          });
        } catch (error) {
          yield { type: "error", data: { nodeId, error: error.message } };
          throw error;
        }
      })
    );
  }

  // 6. 收集 output 节点的数据作为最终结果
  const outputNodes = nodes.filter((n) => n.type === "output");
  const finalOutput = {};
  for (const node of outputNodes) {
    finalOutput[node.id] = context.outputs.get(node.id);
  }

  // 7. 更新执行记录
  await prisma.workflowExecution.update({
    where: { id: execution.id },
    data: { status: "success", output: finalOutput, completedAt: new Date() },
  });

  yield { type: "done", data: { output: finalOutput } };
}
```

## 十一、13 个 Handler 详解

### 文件位置
`src/lib/workflow/handlers/` 下 13 个文件

| Handler | 核心逻辑 |
|---------|---------|
| **trigger** | 直接返回 `context.inputs` |
| **llm** | 解析 systemPrompt + userPrompt 中的变量 → 构建 messages 数组 → 调用 Ollama `chat()` → 返回 `{ content, model, tokenEstimate }` |
| **retrieval** | 解析 query → 调用 `getEmbedding()` 向量化 → 查所有 DocumentChunk → 计算余弦相似度 → 过滤 + 排序 → 返回 top K |
| **condition** | 解析 expression → `evaluateCondition()` → 返回 `{ result: boolean, branch: "true" \| "false" }` |
| **output** | 解析 template → 变量替换 → 可选 JSON.parse → 返回 `{ content, format, parsed }` |
| **http** | 解析 URL/headers/body → `fetch()` + AbortController 超时 → 返回 `{ status, statusText, body, headers }` |
| **intent** | 构建意图识别 prompt（含 categories）→ 调用 Ollama → 返回识别到的意图 |
| **subworkflow** | 解析 inputMapping → 递归调用 `executeWorkflow()` → 返回子流程输出 |
| **code** | `new Function("inputs", "outputs", code)(inputs, outputs)` → 返回 `{ result }` |
| **message** | Webhook: `fetch(url, { method: "POST", body: JSON })` / Email: 占位 → 返回 `{ channel, status }` |
| **loop** | 解析 iterator → 必须是数组 → `Promise.allSettled()` 并行执行 → 返回 `{ total, results, errors }` |
| **varset** | 解析 expression → `context.outputs.set(nodeId, value)` → 返回 `{ value }` |
| **texttemplate** | 解析 template → 变量替换 → 返回 `{ text }` |

## 十二、工作流 API 接口

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/api/workflows` | 获取用户的工作流列表（含节点数和最近执行状态） |
| POST | `/api/workflows` | 创建工作流（初始 draft 状态） |
| GET | `/api/workflows/[id]` | 工作流详情（含最近执行记录） |
| PUT | `/api/workflows/[id]` | 更新工作流（nodes/edges/status） |
| DELETE | `/api/workflows/[id]` | 删除工作流（校验所有权） |
| POST | `/api/workflows/[id]/execute` | 同步执行（等待完成返回结果） |
| POST | `/api/workflows/[id]/execute/stream` | SSE 流式执行（实时推送进度） |
| GET | `/api/workflows/[id]/executions` | 执行历史列表（最近 50 条） |
| GET | `/api/workflows/[id]/executions/[execId]` | 执行详情（含所有节点执行记录） |
| POST | `/api/workflows/executions/[execId]` | 取消执行（标记为 cancelled） |

### 流式执行 API 详解

```typescript
// POST /api/workflows/[id]/execute/stream
// 请求体: { nodes: [...], edges: [...] }  （可选覆盖 DB 中的定义）

// 响应: SSE 流

event: start
data: {"workflowId":"clxxx","executionId":"clxxx"}

event: node
data: {"nodeId":"trigger-1","type":"trigger","status":"running"}

event: data
data: {"nodeId":"trigger-1","data":{...}}

event: layer
data: {"layerIndex":1,"totalLayers":3}

event: node
data: {"nodeId":"llm-1","type":"llm","status":"success"}

event: done
data: {"output":{"output-1":{"content":"结果"}}}
```

**5 分钟超时**: 如果工作流执行超过 5 分钟，连接将自动断开。

## 十三、与其他模块的关系

```
工作流 (Workflow)
  │
  ├── 节点执行依赖
  │     ├── LLM 节点 → Ollama 服务 (ollama.ts)
  │     ├── Retrieval 节点 → 向量嵌入 (embedding.ts) + 知识库 (DocumentChunk)
  │     ├── Code 节点 → JavaScript Function 执行
  │     └── Subworkflow 节点 → 递归执行另一个工作流
  │
  ├── 被智能体引用
  │     └── App.workflowId → 对话时执行工作流代替普通 LLM
  │
  ├── 前端编辑器
  │     ├── React Flow → 可视化 DAG 编辑
  │     ├── 拓扑排序 → 决定执行顺序
  │     └── 变量解析 → {{变量}} → 运行时数据
  │
  └── 执行记录
        ├── WorkflowExecution → 每次执行的输入/输出/错误
        └── NodeExecution → 每个节点的详细执行记录
```
