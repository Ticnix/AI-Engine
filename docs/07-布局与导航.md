# 布局与导航模块

本模块提供应用的整体布局：顶栏（Header）、侧边栏（Sidebar）和主内容区。所有登录后的页面都包裹在此布局中。

## 一、布局架构

```
src/app/(main)/layout.tsx          ← 路由组布局（认证保护）
  ├── MainLayout
        ├── Header                  ← 顶栏
        ├── Sidebar                 ← 侧边栏
        └── {children}              ← 页面内容
```

### 路由组 `(main)`

Next.js 的路由组 `(main)` 是一个特殊的目录命名方式——括号在 URL 中不体现，但允许在此目录下设置共享的 `layout.tsx`。

```
src/app/(main)/
├── layout.tsx         ← 所有子路由共享此布局
├── page.tsx           → /
├── apps/page.tsx      → /apps
├── chats/page.tsx     → /chats
├── knowledge/page.tsx → /knowledge
├── flow/page.tsx      → /flow
└── settings/page.tsx  → /settings
```

URL 中不会出现 `main`，`/apps` 对应的文件是 `src/app/(main)/apps/page.tsx`。

## 二、主布局 — `src/app/(main)/layout.tsx`

```typescript
import { MainLayout } from "@/components/layout";
import { getCurrentUser } from "@/lib/auth";
import { redirect } from "next/navigation";

export default async function MainLayoutWrapper({
  children,
}: {
  children: React.ReactNode;
}) {
  const user = await getCurrentUser();
  if (!user) {
    // 未登录 → 跳转到登录页
    redirect("/login");
  }

  return <MainLayout>{children}</MainLayout>;
}
```

### 双重认证保护

这里实现了**服务端认证检查**，与 `middleware.ts` 形成双重保护：

| 层级 | 文件 | 方式 |
|------|------|------|
| Edge 中间件 | `middleware.ts` | 请求级别的 Cookie 检查 + 重定向 |
| Server Component | `(main)/layout.tsx` | 服务端 `getCurrentUser()` + `redirect()` |

中间件是请求级别的第一道防线，layout 是组件级别的保障（即使中间件因故未生效，layout 也会拦截）。

## 三、MainLayout 组件 — `src/components/layout/main-layout.tsx`

```typescript
import { Header } from "./header";
import { Sidebar } from "./sidebar";
import { useAuthStore } from "@/stores/auth-store";
import { useRef, useEffect } from "react";

export function MainLayout({ children }: { children: React.ReactNode }) {
  const { checkAuth } = useAuthStore();
  const checkedRef = useRef(false);

  // 仅在组件首次挂载时检查一次登录态
  useEffect(() => {
    if (!checkedRef.current) {
      checkedRef.current = true;
      checkAuth();
    }
  }, [checkAuth]);

  return (
    <div className="h-full flex">
      <Sidebar />
      <div className="flex-1 flex flex-col min-w-0">
        <Header />
        <main className="flex-1 overflow-auto p-6">
          {children}
        </main>
      </div>
    </div>
  );
}
```

### 为什么用 `useRef` 防止重复检查？

React 18 的 Strict Mode 在开发模式下会执行两次 `useEffect`。如果没有 `checkedRef` 的保护，`checkAuth()` 会被调用两次，导致多余的 `/api/auth/me` 请求。

### 自动展开逻辑

```typescript
// 根据当前 URL 路径自动展开对应的分组
const pathname = usePathname();

// 路径 → 分组 key 映射
const pathToGroup: Record<string, string> = {
  "/apps": "apps",
  "/chats": "chats",
  "/knowledge": "knowledge",
  "/flow": "flow",
  "/settings": "settings",
};

// 找到当前路径对应的分组
const currentGroup = Object.entries(pathToGroup).find(
  ([path]) => pathname.startsWith(path)
)?.[1];

// 只展开当前分组（single-open 模式）
const [openKeys, setOpenKeys] = useState(currentGroup ? [currentGroup] : []);
```

## 七、ThemeProvider — `src/components/theme-provider.tsx`

```typescript
"use client";

import { useThemeStore } from "@/stores/theme-store";
import { useLayoutEffect } from "react";

export function ThemeProvider({ children }: { children: React.ReactNode }) {
  const mode = useThemeStore((s) => s.mode);

  useLayoutEffect(() => {
    const html = document.documentElement;
    if (mode === "light") {
      html.classList.add("light-mode");
      html.setAttribute("data-theme", "light");
    } else {
      html.classList.remove("light-mode");
      html.setAttribute("data-theme", "dark");
    }
  }, [mode]);

  return children;
}
```

### 为什么用 `useLayoutEffect`？

`useLayoutEffect` 在浏览器绘制前同步执行，避免先渲染暗色再切换到亮色的闪烁问题。

### CSS 主题切换机制

```css
/* 默认暗色主题 */
body {
  background: #001529;
  color: #ffffff;
}

/* 亮色主题通过 .light-mode 类切换 */
.light-mode body {
  background: #f0f2f5;
  color: #000000;
}

/* Ant Design 的 dark 属性控制 */
[data-theme="dark"] .ant-table { /* 暗色表格样式 */ }
[data-theme="light"] .ant-table { /* 亮色表格样式 */ }
```

## 八、布局与路由的关系

```
src/app/layout.tsx                    ← 根布局（所有页面共享）
  └── AntdProvider
        └── src/app/(main)/layout.tsx  ← 主布局包装器（认证检查）
              └── MainLayout
                    ├── Header
                    ├── Sidebar
                    └── {children}     ← 页面内容
                          ├── /           → page.tsx (仪表盘)
                          ├── /apps       → apps/page.tsx
                          ├── /chats/new  → chats/new/page.tsx
                          └── ...

src/app/login/page.tsx              ← 登录页（独立，不使用 MainLayout）
```

登录页不使用 `(main)` 布局，它是独立的全屏页面。只有登录成功后进入 `(main)` 路由组下的页面时，才会出现 Header + Sidebar 的布局。

## 九、状态管理与布局的关系

```
useAuthStore (Zustand)
  ├── 在 Header 中显示用户名和头像
  ├── 在 MainLayout 中 onMount 时 checkAuth()
  └── 在登录表单中 setUser() / logout()

useThemeStore (Zustand + persist)
  ├── 在 Header 中切换主题
  ├── 在 ThemeProvider 中应用 CSS 类
  ├── 在 DocumentSelector 中适配组件样式
  └── 持久化到 localStorage（刷新后保持选择）
```
