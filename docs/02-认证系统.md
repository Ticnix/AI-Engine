# 认证系统模块

本模块负责整个应用的登录注册、Cookie Session 管理和路由级别的身份验证。

## 一、路由中间件 — `middleware.ts`

### 文件位置
项目根目录 `middleware.ts`

### 作用
Next.js 的 Edge Middleware 会在每个请求到达页面前执行。它负责拦截请求，检查用户是否已登录，未登录则重定向到登录页。

### 完整代码

```typescript
import { NextResponse } from "next/server";

// 需要登录才能访问的路径前缀
const protectedPaths = [
  "/flow",
  "/apps",
  "/chats",
  "/knowledge",
  "/settings",
];

// 不需要保护的公开路径
const publicPaths = [
  "/login",
  "/api",
  "/_next",
  "/favicon",
];

function middleware(request: Request) {
  const pathname = request.nextUrl.pathname;

  // 公开路径直接放行
  if (publicPaths.some((p) => pathname.startsWith(p))) {
    return NextResponse.next();
  }

  // 检查是否受保护路径：显式列出 + 根路径（对应 (main) 路由组）
  const isProtected =
    pathname === "/" || protectedPaths.some((p) => pathname.startsWith(p));

  if (!isProtected) {
    return NextResponse.next();
  }

  // 检查 auth_session cookie
  const session = request.cookies.get("auth_session");
  if (!session?.value) {
    // 未登录，重定向到登录页
    const loginUrl = new URL("/login", request.url);
    loginUrl.searchParams.set("from", pathname);
    return NextResponse.redirect(loginUrl);
  }

  return NextResponse.next();
}

export const config = {
  matcher: ["/((?!_next/static|_next/image|favicon.ico).*)"],
};
```

### 逻辑详解

1. **protectedPaths** — 受保护的路径数组：`/flow`、`/apps`、`/chats`、`/knowledge`、`/settings`
2. **publicPaths** — 无需认证的路径：`/login`（登录页）、`/api`（所有 API）、`/_next`（静态资源）、`/favicon`
3. **isProtected** — 除了数组中的路径外，根路径 `/` 也受保护（因为 `(main)` 路由组对应首页）
4. **auth_session Cookie** — 通过 `request.cookies.get("auth_session")` 检查，未登录则跳转到 `/login?from=原路径`
5. **config.matcher** — 正则排除 `_next/static`、`_next/image`、`favicon.ico`，避免无意义的中间件执行

### 与 API 路由的关系

注意中间件对 `/api` 路径是**放行**的（publicPaths 包含 `/api`）。这意味着 API 接口本身不经过中间件认证。认证保护完全由**页面级别的布局**（`src/app/(main)/layout.tsx`）和**API 内部的权限校验**（检查 Cookie 后返回 401）来保障。

## 二、认证工具库 — `src/lib/auth.ts`

### 完整代码

```typescript
import bcryptjs from "bcryptjs";
import { cookies } from "next/headers";
import { NextResponse } from "next/server";
import { prisma } from "./prisma";

const SALT_ROUNDS = 10;
const COOKIE_NAME = "auth_session";

// 密码哈希 — 用于注册时加密
export async function hashPassword(password: string): Promise<string> {
  return bcryptjs.hash(password, SALT_ROUNDS);
}

// 密码验证 — 用于登录时比对
export async function verifyPassword(
  password: string,
  hashedPassword: string
): Promise<boolean> {
  return bcryptjs.compare(password, hashedPassword);
}

// 设置认证 Cookie — 在 Route Handler 中使用，通过 NextResponse 设置
export function createAuthResponse(
  response: NextResponse,
  userId: string,
  rememberMe: boolean = false
): void {
  response.cookies.set(COOKIE_NAME, userId, {
    httpOnly: true,                  // 客户端 JS 无法读取，防 XSS
    secure: process.env.NODE_ENV === "production", // 生产环境仅 HTTPS
    sameSite: "lax",                 // 防 CSRF
    maxAge: rememberMe ? 30 * 24 * 60 * 60 : 24 * 60 * 60, // 30天或24小时
    path: "/",                       // 全站有效
  });
}

// 获取当前用户 ID — 在 Server Component 中使用
export async function getCurrentUserId(): Promise<string | null> {
  const cookieStore = await cookies();
  return cookieStore.get(COOKIE_NAME)?.value || null;
}

// 获取当前用户详情
export async function getCurrentUser() {
  const userId = await getCurrentUserId();
  if (!userId) return null;

  return await prisma.user.findUnique({
    where: { id: userId },
    select: { id: true, email: true, name: true, createdAt: true },
  });
}

// 清除认证 Cookie — 在 Route Handler 中使用
export function clearAuthResponse(response: NextResponse): void {
  response.cookies.delete(COOKIE_NAME);
}

// 清除认证 Cookie — 在 Server Component 中使用
export async function clearAuthCookie(): Promise<void> {
  const cookieStore = await cookies();
  cookieStore.delete(COOKIE_NAME);
}
```

### 关键设计决策

| 函数 | 使用场景 | 为什么有两种 |
|------|----------|-------------|
| `createAuthResponse` | API Route Handler | 通过 `NextResponse.cookies` 设置 Cookie |
| `clearAuthResponse` | API Route Handler | 同上 |
| `getCurrentUserId` | Server Component | 通过 `next/headers` 的 `cookies()` 读取 |
| `clearAuthCookie` | Server Component | 同上 |

**为什么分开？** Next.js 16 中，`next/headers` 里的 `cookies()` 只能在 Server Component 和 Server Action 中调用，不能在 Route Handler 中使用。Route Handler 必须通过 `NextResponse.cookies` 来操作 Cookie。所以同一功能提供了两套 API。

### Cookie 安全配置

```
httpOnly: true       → 浏览器 JS 无法读取，防止 XSS 窃取
secure: true(生产)   → 仅通过 HTTPS 传输
sameSite: "lax"      → 限制跨站请求携带 Cookie，防 CSRF
maxAge: 86400/2592000 → 24小时或30天有效期
path: "/"            → 全站所有路径共享此 Cookie
```

## 四、登录注册组件 — `src/components/auth/auth-card.tsx`

### 完整代码

```typescript
"use client";

import { useState, useEffect } from "react";
import { Tabs, Form, Input, Button, Checkbox, ConfigProvider } from "antd";
import { useRouter, useSearchParams } from "next/navigation";
import { UserOutlined, LockOutlined, MailOutlined } from "@ant-design/icons";
import { useAuthStore } from "@/stores/auth-store";
import { api } from "@/lib/request";

const themeConfig = {
  token: {
    colorPrimary: "#00ffaa",
    colorBgContainer: "transparent",
  },
};

export function AuthCard() {
  const [activeTab, setActiveTab] = useState("login");
  const [loading, setLoading] = useState(false);
  const [form] = Form.useForm();
  const router = useRouter();
  const searchParams = useSearchParams();
  const { setUser } = useAuthStore();

  useEffect(() => {
    // 如果已有认证，直接跳转
    useAuthStore.getState().checkAuth().then((user) => {
      if (user) {
        router.push("/");
      }
    });
  }, [router]);

  const handleLogin = async (values: any) => {
    setLoading(true);
    try {
      const user = await api.post("/api/auth/login", {
        email: values.email,
        password: values.password,
        rememberMe: values.rememberMe,
      });
      setUser(user);
      const from = searchParams.get("from") || "/";
      router.push(from);
    } catch (error: any) {
      // 错误处理
    } finally {
      setLoading(false);
    }
  };

  const handleRegister = async (values: any) => {
    setLoading(true);
    try {
      const user = await api.post("/api/auth/register", {
        email: values.email,
        password: values.password,
        name: values.name,
      });
      setUser(user);
      router.push("/");
    } catch (error: any) {
      // 错误处理
    } finally {
      setLoading(false);
    }
  };

  // 登录表单和注册表单渲染...
}
```

### 逻辑说明

1. **登录**: POST `/api/auth/login` → 验证邮箱密码 → 后端设置 Cookie → 前端存入 authStore → 跳转
2. **注册**: POST `/api/auth/register` → 创建用户 → 后端设置 Cookie（自动登录）→ 跳转首页
3. **from 参数**: 如果从受保护页面被重定向过来（如 `/settings/account`），URL 带有 `?from=/settings/account`，登录成功后自动跳回
4. **主题色**: 使用 `#00ffaa` 青绿色作为主色调，容器背景透明（由外层极光背景衬托）

## 五、登录 API — `src/app/api/auth/login/route.ts`

### 完整代码

```typescript
import { NextResponse } from "next/server";
import { prisma } from "@/lib/prisma";
import { verifyPassword, createAuthResponse } from "@/lib/auth";

export async function POST(request: Request) {
  const body = await request.json();
  const { email, password, rememberMe } = body;

  if (!email || !password) {
    return NextResponse.json({ error: "邮箱和密码是必填项" }, { status: 400 });
  }

  // 查找用户
  const user = await prisma.user.findUnique({ where: { email } });
  if (!user) {
    return NextResponse.json({ error: "邮箱或密码错误" }, { status: 401 });
  }

  // 验证密码
  const isValid = await verifyPassword(password, user.password);
  if (!isValid) {
    return NextResponse.json({ error: "邮箱或密码错误" }, { status: 401 });
  }

  // 通过 NextResponse.cookies 设置认证 Cookie
  const response = NextResponse.json({
    id: user.id,
    email: user.email,
    name: user.name,
    createdAt: user.createdAt,
  });
  createAuthResponse(response, user.id, rememberMe);
  return response;
}
```

### 重要细节

**为什么不用 `cookies()` from `next/headers`？**

在 Next.js 16 的 Route Handler 中，`next/headers` 的 `cookies()` 已不可用。必须通过 `NextResponse.cookies.set()` 来设置 Cookie。这就是 `createAuthResponse` 函数的设计原因——它接收一个 `NextResponse` 实例，往其 Cookie 中写入 `auth_session`。

## 六、注册 API — `src/app/api/auth/register/route.ts`

### 逻辑流程

```
POST /api/auth/register
  ↓
检查 email 和 password 必填
  ↓
检查 password >= 6 位
  ↓
检查邮箱是否已注册 (prisma.user.findUnique)
  ↓
hashPassword(password) — bcrypt 哈希
  ↓
prisma.user.create — 创建用户
  ↓
createAuthResponse — 自动登录（设置 Cookie）
  ↓
返回 201 + 用户信息
```

注册成功后**自动登录**，用户无需再手动登录。

## 十、认证状态管理 — `src/stores/auth-store.ts`

```typescript
import { create } from "zustand";
import { api } from "@/lib/request";

interface AuthState {
  user: any | null;
  isLoading: boolean;
  checkAuth: () => Promise<any>;
  logout: () => Promise<void>;
  setUser: (user: any) => void;
  setLoading: (loading: boolean) => void;
}

export const useAuthStore = create<AuthState>((set) => ({
  user: null,
  isLoading: false,

  // 检查登录态：调用 /api/auth/me
  checkAuth: async () => {
    set({ isLoading: true });
    try {
      const user = await api.get("/api/auth/me");
      set({ user });
      return user;
    } catch {
      set({ user: null });
      return null;
    } finally {
      set({ isLoading: false });
    }
  },

  // 登出：调用 API + 清除本地状态
  logout: async () => {
    try {
      await api.post("/api/auth/logout");
    } catch {}
    set({ user: null });
  },

  setUser: (user) => set({ user }),
  setLoading: (isLoading) => set({ isLoading }),
}));
```

### 使用方式

```typescript
// 组件中
const { user, checkAuth, logout } = useAuthStore();

// 组件外（如 useEffect 中）
useAuthStore.getState().checkAuth();
```

## 十一、认证流程总结

```
用户访问 /settings/account
       ↓
middleware.ts 拦截
  - pathname = "/settings/account"
  - 属于 protectedPaths → 需要认证
  - 检查 auth_session Cookie
       ↓
  [无 Cookie] → 重定向 /login?from=/settings/account
  [有 Cookie] → 放行 → 页面渲染
       ↓
用户登录
  - POST /api/auth/login → 验证密码 → 设置 Cookie
  - 前端存入 authStore → router.push(from)
       ↓
后续请求
  - 浏览器自动携带 auth_session Cookie
  - 中间件放行 → API 可通过 getCurrentUser() 获取用户
```
